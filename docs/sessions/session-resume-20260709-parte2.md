# Decisiones tomadas

## D-01 — Estrategia corp.plan

Se descarta temporalmente la sustitución completa de /speckit.plan.

Se aprueba:

/corp.plan = bootstrap corporativo mínimo

Responsabilidades:

- Leer .specify/memory/active-pbi.md
- Crear features/<feature>/
- Crear spec.md
- Mantener trazabilidad al PBI
- No generar planificación técnica

No genera:

- plan.md
- research.md
- data-model.md
- quickstart.md
- contracts/

La generación de artefactos técnicos continúa siendo responsabilidad de:

/speckit.plan

---

## D-02 — Protección corporativa de speckit.plan

Se añade un guard corporativo al inicio de:

.github/agents/speckit.plan.agent.md

Objetivo:

Impedir que el developer ejecute /speckit.plan sin haber pasado previamente por:

/corp.load
↓
/corp.assess
↓
/corp.plan

El guard verifica:

- existencia de active-pbi.md
- existencia de spec.md
- presencia de los marcadores:

Generated by: /corp.plan

Source of truth:

.specify/memory/active-pbi.md

Si los marcadores no existen:

/speckit.plan queda bloqueado.

# Incidencia detectada en corp.load

## Problema

Durante las pruebas con un PBI real diferente:

resources/7P_PBI-06_crear-solicitud-wizard.md

se detecta que:

/corp.load leía el fichero

pero NO actualizaba:

.specify/memory/active-pbi.md

Consecuencia:

corp.assess y corp.plan continuaban usando:

PBI-1234
Enable users to download shipment documents

aunque se hubiese cargado otro PBI.

---

## Corrección aplicada

Se modifica:

.github/prompts/corp.load.prompt.md

manteniendo únicamente:

---
agent: corp.load
---

Se refuerza el agente para exigir:

1. Lectura del fichero origen.
2. Escritura real de active-pbi.md.
3. Relectura del fichero generado.
4. Validación de que la ruta cargada coincide con el fichero de entrada.
5. Reportar éxito únicamente tras confirmar la escritura.

---

Title:
